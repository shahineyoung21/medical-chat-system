# صباح — تطبيق محادثة طبية تجريبي

**الحالة:** واجهة Flutter عربية قابلة للتجربة، وليست خدمة طبية أو مساعدًا ذكيًا. لا يوجد backend طبي في هذا المستودع بعد.

## ما الذي يعمل؟

- واجهة محادثة عربية باتجاه RTL.
- يمكن كتابة رسالة، لكن الرد تجريبي ثابت ولا يحلل السؤال.
- لا يستخدم التطبيق الشبكة، ولا يرسل الرسائل إلى خدمة، ولا يحفظها بعد إغلاقه.

**لا تستخدمه للتشخيص أو العلاج، ولا تدخل معلومات صحية أو شخصية حقيقية.** عند وجود طارئ صحي، تواصل مع خدمات الطوارئ المحلية أو مختص صحي.

## تشغيل الاختبارات وبناء APK

تحتاج Flutter SDK مستقرًا وJava 17 أو أحدث مناسبًا لقالب Android الحالي.

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

ينتج ملف الاختبار هنا:

```text
build/app/outputs/flutter-apk/app-debug.apk
```

كما يبني GitHub Actions نسخة debug ويرفعها كـArtifact لمدة 7 أيام عند فتح Pull Request إلى `main` أو عند تشغيل الـworkflow يدويًا. بعد رفع الفرع وفتح PR، نزّل Artifact المسمى `sabah-android-debug-apk` من صفحة تشغيل الـworkflow.

## تثبيت نسخة الاختبار على هاتف Android

انقل `app-debug.apk` إلى هاتف Android متوافق، وافتحه واسمح لهذا المصدر بتثبيت التطبيقات عند طلب النظام. نسخة debug مخصصة للاختبار؛ ليست إصدار متجر Google Play ولا نسخة Release موقّعة بمفتاح توزيع.

قبل توزيع Release أو تحديث التطبيق لاحقًا على أجهزة المستخدمين، يلزم اختيار معرف حزمة نهائي ومفتاح توقيع خاص، وحفظ المفتاح خارج GitHub والمستودع. لا تضع ملف keystore أو كلمة مروره في Git أو المحادثة.

## البنية الحالية

- `lib/main.dart`: واجهة المحادثة والردود المحلية فقط.
- `test/widget_test.dart`: اختبارات واجهة بسيطة.
- `android/`: قالب Android الذي يستخدمه Flutter لبناء APK.
- `.github/workflows/main.yml`: تحليل واختبار وبناء APK تجريبي؛ لا يكتب إلى المستودع ولا ينشر التطبيق.

الملف `medical-chat-system.yml` في جذر المستودع ليس Workflow فعّالًا في GitHub Actions. لا تنقله إلى `.github/workflows/` قبل إعادة تصميمه ومراجعته؛ نسخته الحالية تتضمن صلاحيات كتابة وسلوكًا يعلّق على Issues ويدفع إلى `main`.
